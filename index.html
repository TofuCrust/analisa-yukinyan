Tiga Lapisan Blocker (Awalnya Dicurgai Saling Menutupi)

Layer 1: Scanner

Aturan: vol≥5000 AND liq≥5000, ATAU vol≥3000 AND liq≥20000 (floor 3000 di dual-path)

Implikasi: Market high-liquidity-low-volume (contoh: 76ers vs Knicks vol $212 liq $47k) tidak pernah lolos.

Catatan: floor 3000 tidak punya justifikasi tertulis.

Layer 2: Audit

Masalah: coverage_audit semantik stale.

Definisi stale: event_start < now_utc → di-skip.

Implikasi: Market low-volume yang lolos pagi sudah stale ketika audit jalan sore. Hasil: coverage_audit selalu lapor 0 below-gate matchups.

Layer 3: Adapter (The Real Culprit)

Adapter NBA v1.5 sudah real, unit test pass. Tapi belum pernah dipanggil manual pada matchup nyata saat runtime.

Kesimpulan: Tidak tahu apakah benar bisa COMPLETE atau tidak sebelum dieksekusi terpisah.

03 Yang Sudah Dicoba & Hasilnya

Log iterasi troubleshooting selama investigasi Phase 2. Eksperimen dilakukan secara berurutan untuk mengupas layer demi layer dari blocker.

Eksperimen 1: Cleanup scope scanner (~2 minggu lalu)

Hipotesis: Scanner kemasukan futures, draft, totals, spread → menghasilkan noise.

Action: Filter futures keywords, partial games (1H/1Q), award futures, draft, coach movement.

Hasil: Scanner jauh lebih bersih, fokus ke pregame matchup/moneyline.

Kesimpulan: Bagus, tapi tidak menyelesaikan blocker utama (tetap 0 candidates).

Eksperimen 2: Tuning shadow threshold + dual-path

Hipotesis: Threshold scanner terlalu ketat.

Action: Turunkan ke vol≥5000 / liq≥5000, tambahkan dual-path vol≥3000 AND liq≥20000.

Hasil: Tetap 0 candidates di run 24 iterasi (window 13:03–14:58 WIB).

Kesimpulan: Melonggarkan threshold tidak cukup; ada blocker lain.

Eksperimen 3: Build scan_monitor untuk observability

Hipotesis: Kita perlu data runtime untuk diagnosa.

Action: Tool yang catat total_candidates, quality_complete, quality_partial per iterasi.

Hasil: 24 iterasi semua 0 candidates, 0 COMPLETE, 0 PARTIAL.

Kesimpulan: Scanner tidak meloloskan apapun selama window observasi.

Eksperimen 4: Build coverage_audit untuk paksa audit adapter

Hipotesis: Butuh tool yang paksa audit adapter pada market below-gate.

Action: coverage_audit yang scan market low-volume, jalankan adapter.

Hasil: 0 below-gate matchups (karena freshness check menyaring duluan).

Kesimpulan: Tool jadi, tapi tidak memberi bahan validasi adapter.

Eksperimen 5: Build standalone proof tool untuk adapter (HARI INI)

Hipotesis: Adapter mungkin belum benar-benar berjalan runtime, tapi kita tidak tahu karena scanner blokir duluan.

Action: Panggil NBAAdapter.fetch_raw() + parse_payload() langsung di luar scanner, pada matchup NBA aktif.

Hasil run 1 (4 matchup default, mix aktif + eliminated): 4/4 PARTIAL
Hasil run 2 (4 matchup 100% aktif Round 2 playoffs): 1/8 tim COMPLETE (76ers), 7/8 PARTIAL

Kesimpulan: Blocker BUKAN scanner. Blocker adalah parser ESPN schedule yang require ≥10 completed games.

04 Akar Masalah & Tiga Opsi Solusi

Akar Masalah Teridentifikasi

File: source_adapters/nba.py, baris 369-374, fungsi _parse_espn_schedule()

Logika: if len(completed) < 10: return None

Realita: ESPN team schedule endpoint kembalikan playoff games saja (kemungkinan, perlu konfirmasi). Untuk tim Round 2 playoffs awal Mei, completed playoff games = 5-9, di bawah threshold.

Bukti: 76ers (10 completed: 7 game R1 + 3 game R2) lolos. Knicks (R1 + 3 R2 = ~7) gagal. Lakers, Thunder, Pistons, Cavs, Spurs, Wolves: semua gagal dengan pola sama.

⚠ Yang Penting:

Threshold 10 BUKAN heuristik liar. Ini bagian definisi metrik form yang konsisten di tiga modul:

  • _parse_espn_schedule() — tolak < 10
  • _parse_l10() — terima actual hanya kalau w+l==10
  • _compute_form_gap() — formula (wa - wb) / 5.0 mengasumsikan window 10 game dengan baseline netral 5

Mengubah threshold di satu tempat tanpa koordinasi tiga modul → metrik rusak.

Decision Tree: Tiga Opsi Solusi

Opsi C

Investigate

Investigate ESPN endpoint

Action: Cari parameter (seasontype=2,3 atau season=2026&dates=...) yang buka window regular season + playoff.

Effort: 30-60 menit eksperimen.

Benefit: Kalau berhasil, fix 1 baris di _fetch_espn_schedule(). Definisi metrik tetap utuh, COMPLETE achievable.

Risiko: Kalau ESPN strict postseason-only, waktu ini sia-sia.

Reversibility Tinggi

Opsi E

Pause

Tunda Phase 2 ke Oktober

Action: Dokumentasikan temuan, bekukan Phase 2 gate validation, lanjut ke Phase 3 (AI analyzer) atau pause.

Effort: Nol kode, dokumentasi saja.

Benefit: Paling jujur. Definisi metrik utuh. Sejajar dengan "Conservative-first". Tidak ada technical debt.

Risiko: Timeline mundur 4-5 bulan. Stakeholder kecewa.

Reversibility Tinggi

Opsi F

Redesign

Redesign metrik form (N variable)

Action: Pindah dari "L10 actual" ke "L_N actual dengan N≥5". Update 3 modul terkoordinasi. Dokumentasi diff.

Effort: 1-2 hari engineering + verification.

Benefit: Phase 2 dibuka selama playoffs. Adapter bisa COMPLETE.

Risiko: Skala formula berubah. Skor antar musim tidak comparable. Risk register R-09 (tuning bias) berlaku.

Reversibility Rendah
Rekomendasi Awal:
Mulai dengan Opsi C dulu (cek murah 30-60 menit). Kalau gagal → diskusi C/E/F dengan stakeholder. Ini bukan keputusan engineering tunggal karena menyangkut validitas statistik sistem.
