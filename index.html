2. Apa yang Sedang Dibangun

NekoSport adalah bot otomatis untuk pasar prediksi olahraga di Polymarket. Saat ini sistem berada di mode shadow (analisis tanpa eksekusi nyata). Versi 1 (v1) menemui limitasi (stuck) karena mengandalkan single-source (hanya ESPN) dan rule engine yang deterministik serta kurang fleksibel merespons dinamika pasar. v2 dirancang untuk menyelesaikan limitasi ini melalui arsitektur baru.

v1 (Sekarang)

  • ✗ Single source (ESPN)
  • ✗ Rule engine deterministik
  • ✗ No hedging
  • ✗ Stuck di Phase 2
→

v2 (Target)

  • ✓ Multi-source (ESPN + Basketball-Reference)
  • ✓ AI synthesizer dengan guardrails
  • ✓ Hedging sebagai risk management
  • ✓ Live target 10 Juni 2026

*Catatan Polymarket: Ini bukan sentimen, melainkan data otoritatif untuk market yang kita trade.

⚠ Warning: Limitasi Basketball-Reference

Sports Reference LLC (operator) tidak menyediakan API resmi. Akses mengandalkan scraping HTML. Mereka memiliki kebijakan ketat (maksimal ~20 request/menit, ban IP untuk repetisi) karena beban server HTML dan perlindungan model bisnis (langganan premium Stathead).

Mitigasi NekoSport:
  • Cache TTL agresif: 6 jam untuk data historis, 1 jam untuk current.
  • Throttling: Minimal 3 detik antar request. Scan NBA playoffs (~6 markets) butuh ~12 request (aman di bawah limit).
  • Fallback Quality: Jika terkena limit (429/IP ban), fallback ke data quality MINIMAL untuk scan terkait (mencegah crash).

Plan B Blokir Permanen: Switch ke halaman ESPN team-vs-team, atau tunda metrik head-to-head ke scope v2.1.

Disclaimer: Analisis sentimen Reddit/news di-defer ke v3 karena scope NLP membutuhkan tambahan waktu yang tidak available di timeline saat ini.

4. Data Flow End-to-End

Berikut adalah alur data eksekusi bot. Arsitektur bergeser dari rule-based murni menjadi AI Synthesizer dengan Strict Guardrails.

1. Trigger Sistem +
Cron scheduler harian
Pemicu utama dijalankan dua kali sehari: Pukul 09:00 WIB dan 20:00 WIB untuk menangkap dinamika pasar pregame.
2. Polymarket Scan +
Ambil market NBA pregame aktif
Menarik list market dari API Polymarket internal. Memfilter hanya market yang berkaitan dengan NBA Playoffs dan berstatus pregame.
3. Parallel Fetch (Multi-source) +
ESPN & Basketball-Reference
  • ESPN: standings, recent form, schedule.
  • Basketball-Ref: H2H historis, advanced stats.
Proses berjalan paralel per market dengan internal throttling untuk B-Ref.
4. Triangulation Engine +
Konsolidasi metrik & quality scoring
  • Konsolidasi metrik dari berbagai source.
  • Hitung disagreement score (jika source memberikan sinyal bertolak belakang).
  • Assign Quality Level: HIGH, MINIMAL, DEGRADED, atau FAIL.
HARD GATE: Quality DEGRADED/FAIL → SKIP
5. Math / Rule Engine +
Input layer sebelum AI
Menghitung Expected Value (EV), Kelly fraction, dan rekomendasi stake (base size). Memberikan flag status gate untuk bahan referensi AI.
6. AI Synthesizer (Claude Sonnet 4.6) +
Core Decision Engine
Input: Triangulated data + output EV/Kelly dari rule engine.
Output: Keputusan final (BUY/SKIP) + size modifier + rekomendasi hedge + reasoning trace (alasan logis).
GUARDRAIL #1: AI Validator
- Schema valid?
- Reasoning trace valid?
- Decision tidak contradictory?
GUARDRAIL #2: Risk Engine (Non-overrideable)
- Daily loss cap, Max concurrent, Hedge cap
- Emergency stop
7. Execution & Logging
  • Mode: Shadow / Paper / Live (dikontrol manual oleh operator).
  • Persist: Save to Database + kirim Telegram report.

5. Decision Logic

Kondisi yang menentukan apakah bot melakukan SKIP atau eksekusi BUY.

✗ SKIP Otomatis

(Hard gate, tidak bisa di-override)

  • Data quality DEGRADED atau FAIL.
  • AI output gagal validasi setelah 1x retry.
  • Reasoning trace kosong atau tidak reference input.
  • Volume/liquidity/spread di luar threshold per segment.
  • Risk gate violated.

✓ BUY Execute

(Semua kondisi di bawah terpenuhi)

  • Data quality MINIMAL ke atas.
  • AI decision = BUY dengan reasoning trace valid.
  • Risk gates pass (aman dari limit).
  • Execution mode allow trading (paper/live).

Size Scaling Logic

  • Base: Kelly fractional dari rule engine.
  • AI Modifier: AI dapat memberikan modifier 0.5 - 1.5x (cap maksimal 1.5x untuk safety).
  • Absolute Cap: Hard cap dari risk engine tetap berlaku sebagai final gate.

6. Hedging Logic (First-Class Feature)

Kapan AI akan menyarankan Hedge?

High Disagreement
Multi-source disagree tinggi, tetapi AI tetap confident untuk BUY primary.
Split Signals
Sebagian data menunjukkan indikator bullish, sebagian bearish.
Market Opportunity
Market dengan liquidity tinggi di kedua sisi (memungkinkan exit hedge dengan low slippage).

Spesifikasi Hedge v2

  • Side: Berlawanan dari primary.
  • Size: 50% dari primary (fixed ratio).
  • Timing: Immediate setelah primary entry confirmed.
  • Registry: Same market_id, masuk ke tabel hedge_pairs.

Hedge dibatalkan jika:

  • Primary gagal entry.
  • Risk engine block (total exposure primary + hedge melebihi cap maksimum).
  • Mode shadow (hanya log niat hedge, tidak eksekusi nyata).

Effectiveness Tracking

  • Evaluator menghitung PnL pair (primary + hedge) vs hypothetical (primary saja).
  • Jika hedge consistently merugikan pada segment tertentu, auto-disable untuk segment tersebut.

Catatan: Rolling hedge dan variable ratio bersifat out-of-scope untuk v2. Akan dipertimbangkan di v3 setelah v2 stabil.

7. Antisipasi Pertanyaan: "Kenapa Tidak Pakai AI Web Scraping?"

Workflow manual dengan ChatGPT (mencari web → membaca 10-20 artikel → sintesis → ambil keputusan) sangat efektif untuk manusia. Namun, untuk implementasi bot otomatis dengan target go-live 10 Juni, terdapat 4 alasan teknis mendasar mengapa jalur tersebut tidak kita tempuh.

1. Cost Multiplier (Biaya 10-50x Lipat)

Pendekatan Cost per AI call Calls/hari Cost/bulan
Structured data + AI Synthesizer (v2) ~$0,025 (dengan caching) 12 ~Rp 150.000
AI Web Scraping per market ~$0,50-1,00 (estimasi kasar)* 12 ~Rp 2.500.000-5.000.000

*Web scraping butuh input token raksasa (50k-100k) untuk parse HTML mentah. Angka $0.50-$1.00 adalah estimasi perbandingan kasar berdasarkan volume token tipikal.

2. Latency 5-10x Lebih Lambat

Pendekatan Per-market latency 12 markets total
Structured data parallel fetch 2-5 detik 30-60 detik
AI web scraping sequential 30-60 detik 6-12 menit

Scanner harus cepat (< 2 menit). Delay 12 menit berisiko harga pasar bergerak drastis, membuat analisis obsoleto saat dieksekusi.

3. Audit Trail Rusak

Google search results berubah real-time. Jika kita mereplay decision minggu lalu, data sudah tidak sama. Arsitektur Structured Data menjamin auditability yang solid (data source tersimpan, replay decision menghasilkan AI reasoning yang konsisten).

4. Kemunduran Timeline

Membangun pipeline NLP/Scraping yang robust anti-bot butuh 2-3 minggu tambahan khusus untuk engineering integrasi web tool. Target live trade untuk NBA Final 10 Juni menjadi tidak achievable.

Kesimpulan: Structured data + AI synthesizer adalah trade-off terbaik untuk akurasi, cost, latency, dan timeline. AI Web Scraping akan dipertimbangkan untuk v3 sebagai augmentation layer (bukan replacement) setelah v2 terbukti profitable.
